# 11 Installation and Deployment

## Prerequisites and versioned dependencies

The repository targets Node.js 24 or later and Python 3.12 through 3.14; the development baseline is Python 3.12. Use pnpm 11.25.0 as documented in the repository. The frontend lockfile and backend dependency files record the actual package selections. Later versions are not automatically implied to be compatible.

| Component | Pinned direct versions |
| --- | --- |
| Frontend framework and routing | React 19.3.1; React DOM 19.3.1; React Router DOM 7.18.5 |
| Visualization | React Flow 12.12.1; Recharts 3.10.1; Lucide React 1.70.0 |
| Frontend tooling | Vite 8.3.7; TypeScript 6.0.3; Tailwind CSS 4.3.5; Vitest 5.1.0 |
| Backend web stack | FastAPI 0.162.2; Uvicorn 0.54.0; pydantic-settings 2.16.2; python-multipart 0.0.33 |
| Data and mining | Pandas 2.3.3; PM4Py 2.7.23.12 |
| Backend test and lint tools | pytest 9.2.0; HTTPX 0.28.1; Ruff 0.17.4 |

Use a project virtual environment rather than installing backend dependencies into a shared Python environment. If pnpm is unavailable, install the documented version with `npm install --global pnpm@11.25.0`. Initial dependency installation requires access to the package registries.

## Windows installation and startup

Open two PowerShell terminals at the project root. In the backend terminal:

```powershell
cd backend
py -3.12 -m venv .venv
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

In the frontend terminal:

```powershell
cd frontend
Copy-Item .env.example .env
pnpm install --frozen-lockfile
pnpm dev
```

Copy environment examples only during initial setup; preserve existing local values when restarting. Subsequent starts need only the Uvicorn and pnpm development commands. Stop each server with Ctrl+C in its own terminal. The original supplied GIU logo is already under `frontend/public/brand/giu_logo.jpg`; it is not regenerated by installation.

## macOS and Linux equivalents

From the project root, in the backend terminal:

```bash
cd backend
python3.12 -m venv .venv
cp .env.example .env
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

In a second terminal, run `cd frontend`, copy `.env.example` to `.env`, then run `pnpm install --frozen-lockfile` and `pnpm dev`. These commands follow the repository setup; this documentation audit executed the Windows environment, not a new macOS or Linux installation.

## Environment configuration

| Setting | Default | Purpose |
| --- | --- | --- |
| HR_APP_ENV | development | Environment label; does not itself add production controls |
| HR_LOG_LEVEL | INFO | Backend logger verbosity |
| HR_CORS_ORIGINS | localhost and 127.0.0.1 on port 5173 | JSON array of explicit allowed browser origins |
| HR_DATASET_STORAGE_DIR | runtime/datasets | Local storage; relative values resolve under backend/ |
| HR_MAX_UPLOAD_BYTES | 52,428,800 | 50 MiB maximum CSV size; configurable downwards |
| HR_MAX_ROWS | 250,000 | CSV record bound; configurable downwards |
| HR_MAX_COLUMNS | 200 | CSV column bound; configurable downwards |
| HR_PREVIEW_ROWS | 20 | Maximum preview records; configurable downwards |
| HR_INDUCTIVE_MAX_EVENTS | 50,000 | Per-process eligible event limit for Inductive Miner |
| HR_INDUCTIVE_MAX_ACTIVITIES | 100 | Per-process activity-label limit for Inductive Miner |
| VITE_API_BASE_URL | /api/v1 | Browser-visible REST prefix |
| API_PROXY_TARGET | http://127.0.0.1:8000 | Vite development proxy destination |

Frontend `VITE_` variables are public browser configuration and must not contain secrets. Backend `.env` is read relative to the backend application. Restart the relevant server after configuration changes. If ports change, align the frontend API/proxy setting and backend allowed origins. Vite uses strict port selection, so an occupied port must be resolved rather than silently switching addresses.

## Local access and connection verification

| Service | Address |
| --- | --- |
| Application | http://127.0.0.1:5173 |
| Direct API health | http://127.0.0.1:8000/api/v1/health |
| Health through frontend proxy | http://127.0.0.1:5173/api/v1/health |
| Interactive API documentation | http://127.0.0.1:8000/api/docs |
| OpenAPI schema | http://127.0.0.1:8000/api/openapi.json |

Both health addresses should identify `hr-process-mining-api` with status `ok`. The frontend connection indicator reports its latest check; it is not continuous uptime monitoring. Begin at a fresh application URL to verify the empty state. Upload the separately supplied `event_log.csv` only when deliberately testing; no dataset is bundled as an automatic default.

## Repeatable verification

From `frontend/`:

```text
pnpm typecheck
pnpm test
pnpm build
```

From `backend/` on Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check app tests scripts
```

On macOS/Linux replace the interpreter path with `.venv/bin/python`. Linting is a repeatable maintenance command; executed results are reported separately in Chapter 9. A frontend build creates `frontend/dist/`. `pnpm preview` serves that build locally on port 4173, but its configuration does not reproduce the development API proxy; configure an actual API URL and allowed origin or a reverse proxy before treating preview as a connected application.

For functional evaluation, upload, map, validate and confirm the supplied fixture, watch the real analysis stages, visit all five sections, inspect a case and a finding, and open a saved explicit dataset URL. These are test instructions, not assertions that every future environment has passed them.

## Deployment boundary and troubleshooting

The documented configuration is for local development and research. Vite's development server and proxy are not a production deployment. A future deployment must serve the frontend build with an SPA fallback, route `/api` to FastAPI, and add the security, ownership, worker durability and operational controls described in Chapter 10. Run the existing backend as one application process; multiple independent workers are incompatible with its in-memory locking assumptions.

If the frontend loads but the health check fails, verify that the backend is running on the configured port and that the proxy target is correct. If upload succeeds but validation fails, use the reported row examples and mapping settings to correct the actual issue. A missing saved dataset may reflect a different storage directory or absent copied runtime files. Interrupted analysis requires retry; restarting does not resume the worker automatically. Do not diagnose a stale result by deleting unrelated datasets.
